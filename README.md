# Труба

Домашняя сеть через собственный VPS: **Труба** (VPS на Ubuntu 24.04) отдаёт **Роутеру** (ImmortalWrt 25.12) весь свой публичный IP по **Туннелю** AmneziaWG, а Роутер сам решает, какой трафик пускать через Туннель, и делает Full cone NAT. Трафик распределяется по Категориям из [geoip.dat](https://github.com/kirilllavrov/geoip-builder) и [geosite.dat](https://github.com/kirilllavrov/geosite-builder), которые используются без изменений. Всё управляется из LuCI: «Службы → Труба».

Версия 1.2 — что в неё входит, в [CHANGELOG.md](CHANGELOG.md).

## Установка

### 1. Фид пакетов (один раз)

AmneziaWG нет в фидах ImmortalWrt, а сторонние сборки модуля ядра не совпадают с ядром ImmortalWrt, поэтому пакеты собирает CI репозитория ([ADR 0004](docs/adr/0004-own-apk-feed-over-stock-firmware.md)).

1. Репозиторий: [github.com/LaKardo/truba](https://github.com/LaKardo/truba).
2. Создайте ключ подписи фида и добавьте его в **Settings → Secrets and variables → Actions**:
   ```bash
   openssl ecparam -name prime256v1 -genkey -noout -out truba-feed.pem
   ```
   ```bash
   openssl ec -in truba-feed.pem -pubout > truba-feed.pub.pem
   ```
   `APK_SIGN_KEY` — содержимое `truba-feed.pem`, `APK_SIGN_PUB` — содержимое `truba-feed.pub.pem`. Закрытый ключ в репозиторий не кладите.
3. **Actions → build → Run workflow**. После сборки включите **Settings → Pages → ветка `gh-pages`**. Эта ветка и есть фид: её не удаляют и не правят вручную.
4. Фид появится по адресу `https://lakardo.github.io/truba/<версия>/mediatek/filogic/packages.adb`.

`watch-releases` каждый день проверяет новые ImmortalWrt 25.12.x и сам собирает под них пакеты.

### 2. VPS

Нужны: Ubuntu 24.04, полноценная ВМ (KVM, VMware, Xen, Hyper-V; не контейнер), публичный IPv4 прямо на интерфейсе, SSH-ключ в `/root/.ssh/authorized_keys`.

```bash
curl -fsSLO https://raw.githubusercontent.com/LaKardo/truba/main/vps/install-vps.sh
```
```bash
sudo bash install-vps.sh install
```

Скрипт временно оставит SSH и на прежнем порту (обычно 22-м), и на новом и попросит войти по новому порту из другого окна. Без подтверждения за 120 с всё откатится; если сессия оборвётся, откат сделает сам скрипт или, если он не успеет, отдельный таймер systemd. Поэтому скрипт нужно скачать в файл, как выше, а не запускать через `bash <(curl …)`. После установки:

- порт 22 и все остальные порты IP VPS уходят на Роутер, SSH самого VPS — только на новом порту;
- MTU Туннеля подобран под сеть VPS: 1380 при обычной 1500, меньше, если сеть у провайдера уже (например, 1298 при 1400). Если путь до дома ещё уже (PPPoE, мобильная связь), `mtu-check` это покажет, а `install --mtu N` задаст MTU вручную;
- если модуль поддерживает AmneziaWG 3.1, Туннель сразу получает защиту заголовков (`HeaderProtectionKey`), включённую cookie-защиту от нагрузки рукопожатиями (`DisableCookies = off`), случайную добавку к пакетам данных (`ContentPaddingAddition`: их длины не кратны 16) и keepalive Роутера со случайным периодом 15–25 с;
- DSCP пакетов Туннеля обнуляется на обеих сторонах: иначе рукопожатие уходит с меткой AF41, как у WireGuard;
- на адресе Трубы в Туннеле (`10.77.77.1`) работает DNS-сервер для Роутера (unbound): он пересылает запросы по TLS в Cloudflare и Google, поэтому новые имена через Туннель резолвятся без лишних задержек ([ADR 0013](docs/adr/0013-tunnel-dns-server-on-vps.md)). Роутер обращается к нему сам: это первый сервер «Туннеля» по умолчанию;
- `/root/truba/router.conf` — конфиг для Роутера. Заберите его:
  ```bash
  scp -P <SSH-порт> root@<IP VPS>:/root/truba/router.conf .
  ```

Команды: `install-vps.sh install [--ssh-port N] [--awg-port N] [--mtu N|auto] [--no-confirm] | status | show-config | mtu-check | diag [секунд] | repair-module | rotate-keys | random-trailers on|off | uninstall [--purge]`. `repair-module` собирает модуль amneziawg для ядер, у которых его нет (об этом предупреждает `status`). `diag` замеряет потери, упоры в процессор и задержку Туннеля; запустите его в простое и во время скачивания через Туннель. Без `--ssh-port` и `--awg-port` порты выбираются случайно из 40000–59999. `--no-confirm` пропускает проверку входа по новому порту — нужен, если терминала нет (например, скрипт запущен из cloud-init); если новый порт закрыт у провайдера, войти на VPS будет нельзя.

`RandomTrailers` лежит в запасе — на случай, если DPI начнёт узнавать Туннель по размерам пакетов. Он увеличивает трафик на мелких пакетах, поэтому по умолчанию выключен. Включать надо на обеих сторонах сразу:

```bash
install-vps.sh random-trailers on
```

Затем на Роутере импортируйте `router.conf` заново: **Службы → Труба → Туннель → Импорт .conf**. Одного флага Random Trailers мало: вместе с ним снимается добавка к пакетам, которую модуль взял бы вместо него. Выключается так же: командой `off` и новым импортом.

### 3. Роутер (ImmortalWrt 25.12, Netcraze NC-1812)

```bash
wget -O /etc/apk/keys/truba.pem https://lakardo.github.io/truba/keys/truba.pem
```
```bash
. /etc/os-release; echo "https://lakardo.github.io/truba/${VERSION}/mediatek/filogic/packages.adb" > /etc/apk/repositories.d/truba.list
```
```bash
apk update && apk add kmod-amneziawg amneziawg-tools luci-proto-amneziawg truba luci-app-truba luci-i18n-truba-ru luci-app-upnp
```

netifd узнаёт о новом протоколе `amneziawg` только при запуске, поэтому перезапустите сеть (или роутер). Без этого интерфейс Туннеля не поднимется (`proto none`, `NO_DEVICE`). Связь пропадёт секунд на 20–30:

```bash
/etc/init.d/network restart
```

Затем в LuCI:

1. **Службы → Труба → Туннель → Импорт .conf** — вставьте `router.conf` → **Сохранить и применить**.
2. **Обзор** — Туннель «работает», рукопожатие свежее, IP Трубы виден.
3. **Правила** — Режим и Действия Категорий (Стартовые настройки уже выставлены).

При установке пакет сам создаёт зону `truba`, включает fullcone и выключает аппаратное ускорение, а служба закрывает выход в интернет по IPv6 каждой зоне из «Правила → Зоны». Программное ускорение он не трогает: при нём пакеты ускоренных соединений идут мимо счётчиков Трубы и мимо шейперов трафика, о чём предупреждает «Обзор». IPv6 внутри сети он тоже не трогает. При удалении пакета всё это откатывается, а Наборы правил и другие данные службы удаляются. Не выключайте IPv6 на `br-lan` (`network.lan.ipv6`): по нему mesh-узлы находят друг друга.

## Как пользоваться

| Вкладка | Что там |
|---|---|
| Обзор | Строка состояния: всё ли работает, задержка и рукопожатие, IP Трубы, переключатели «Туннель» и «Маршрутизация». Схема «куда идёт трафик» (устройства → Роутер → Туннель или Напрямую) со скоростью сейчас; карточка Туннеля; скорость за 10 минут, час или сутки и объёмы по Действиям; пять самых активных устройств; DNS и Наборы правил, входящие и NAT; предупреждения со ссылкой туда, где их исправляют. Историю скорости ведёт сам Роутер в оперативной памяти: график не рвётся, когда вкладка свёрнута или браузер закрыт, и обнуляется при перезагрузке |
| Устройства | Кто в домашней сети сколько качает и через что: скорость сейчас, доля Туннеля и Напрямую, объём за сутки; поиск и фильтры. Панель устройства: Политика по MAC («По правилам», «Всё в туннель», «Всё напрямую»), имя, график за час, куда оно ходит сейчас (адреса из таблицы соединений с Действием и причиной), «Проверить» для этого устройства. Устройство можно добавить по MAC заранее |
| Правила | «Куда пойдёт» — какая Категория и какое Действие сработают для домена или IP и почему. Режим, переключатель «Маршрутизация», зоны. Наборы правил: версии, итог последней проверки, «Обновить сейчас» и «Откатить», расписание и источники. Категории с поиском, фильтром по Действию и выбором Действия; «Стартовые настройки» |
| Туннель | Состояние: задержка, рукопожатие, потери, крупные пакеты, график задержки, таблица Туннеля, трафик интерфейса. Подключение к Трубе: адрес, протокол, MTU, keepalive, «Проверить Туннель» (ping пакетами трёх размеров до всего MTU). Что делать, когда Туннель не отвечает: контроль Туннеля и Аварийная блокировка. Ключи и параметры AmneziaWG: импорт `router.conf` (файл или вставка) и параметры AWG группами, в том числе AmneziaWG 3.1; пока Туннель не настроен, импорт — в «Подключении к Трубе» |
| DNS | Состояние mosdns и кэша: доля ответов из кэша и из истёкшего кэша, заполнение, запросов с запуска. Серверы для «Туннеля» и «Напрямую», перехват DNS устройств, кэш (в том числе ленивый) и срок адресов из DNS в наборах |
| Входящие | Проверка NAT: итог последней проверки (сама запускается после подъёма Туннеля) и кнопка. UPnP/NAT-PMP на Туннеле и его действующие пробросы. Пробросы портов из Туннеля: добавить, изменить, включить или выключить, удалить — секции межсетевого экрана с источником `truba` |
| Журнал | Последние строки Трубы, её контроля Туннеля, mosdns и интерфейса Туннеля: фильтр по уровню и источнику, «Следить», «Скачать» в `.txt` |

Изменения копятся в браузере: внизу страницы панель показывает, сколько их, а несохранённые поля и строки отмечены точкой. «Применить» на ней — то же, что **«Сохранить и применить»** LuCI, с откатом: служба `truba` сама включает или снимает правила nftables, маршруты, mosdns, перенаправление dnsmasq, cron и контроль Туннеля. Поле с неверным значением подсвечено, и применить, пока оно такое, нельзя.

Если применить не удалось, служба не останавливается и DNS сети не пропадает: действуют прежние правила, а после перезагрузки — последняя удачная копия, сохранённая на флеше ([ADR 0006](docs/adr/0006-failed-apply-keeps-last-good-rules.md)). Ошибку и то, что действует вместо неё, показывает «Обзор». Неверное значение в настройках (например, MAC или адрес DNS-сервера с опечаткой) пропускается, вместо него берётся значение по умолчанию, и «Обзор» об этом предупреждает. Скачанный Набор правил, который не разбирается, текущий не заменяет.

Из командной строки (`truba` без аргументов — список команд):

```bash
truba status
```
```bash
truba check gosuslugi.ru
```
```bash
logread -e truba
```

## Обновление

**Пакеты Роутера** обновляйте вместе — интерфейс и служба одной версии:

```bash
apk update && apk upgrade truba luci-app-truba luci-i18n-truba-ru
```

**Труба.** Скачайте свежий `install-vps.sh` и запустите `install` ещё раз: ключи и порты сохранятся, а очередь, заголовки ядра, MTU и DNS-сервер для Роутера приведутся к текущим. Туннель перезапускается, только если его конфиг изменился. Если на вкладке **DNS** среди серверов «Туннеля» нет `udp://10.77.77.1`, добавьте его: запрос идёт ко всем серверам сразу, порядок не важен. Если изменился `router.conf` (адрес, порт или MTU Туннеля), `install` скажет об этом — импортируйте его в Роутер заново или поставьте новый MTU вручную: **Службы → Труба → Туннель → MTU → Сохранить и применить**. Действующий MTU показывает строка `MTU Туннеля` в выводе `install-vps.sh status`. Повторный `install` параметры AWG не меняет. Чтобы перейти на новую версию протокола (например, AmneziaWG 3.1), выполните `rotate-keys` и импортируйте `router.conf` в Роутер заново.

**ImmortalWrt.** Обновляйте Роутер только после того, как в фиде появился каталог новой версии (`watch-releases` собирает его автоматически). После sysupgrade настройки и ключ фида сохраняются, а `/etc/truba/reinstall.sh` из `rc.local` сам ставит пакеты заново. Если модуля ядра под новую версию ещё нет, Туннель не поднимется: скрипт пишет в журнал, как доставить модуль, когда сборка появится.

## Проверки

Все проверки идут в Docker, независимые части — параллельно:

```bash
bash tests/run.sh
```

Что проверяет каждая часть и как запускать их по отдельности — в [tests/README.md](tests/README.md). На pull request CI гоняет те же части. Приёмочные тесты на живой сети (Full cone по RFC 5780, входящие, утечки) — в [docs/roadmap.md](docs/roadmap.md#приёмочные-тесты).
