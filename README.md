# Труба

Домашняя сеть через собственный VPS: **Труба** (VPS на Ubuntu 24.04) отдаёт **Роутеру** (ImmortalWrt 25.12) весь свой публичный IP по **Туннелю** AmneziaWG, а Роутер сам решает, какой трафик пускать через Туннель, и делает Full cone NAT. Трафик распределяется по Категориям из [geoip.dat](https://github.com/kirilllavrov/geoip-builder) и [geosite.dat](https://github.com/kirilllavrov/geosite-builder), которые используются без изменений. Всё управляется из LuCI: «Службы → Труба».

Версия 1.1 — что в неё входит, в [CHANGELOG.md](CHANGELOG.md).

## Установка

### 1. Фид пакетов (один раз)

AmneziaWG нет в фидах ImmortalWrt, а сторонние сборки модуля ядра не совпадают с ядром ImmortalWrt, поэтому пакеты собирает CI репозитория ([ADR 0004](docs/adr/0004-own-apk-feed-over-stock-firmware.md)).

1. Репозиторий: [github.com/LaKardo/truba](https://github.com/LaKardo/truba).
2. Создайте ключ подписи фида и добавьте его в **Settings → Secrets and variables → Actions**:
   ```bash
   openssl ecparam -name prime256v1 -genkey -noout -out truba-feed.pem
   ```
   ```bash
   openssl ec -in truba-feed.pem -pubout > truba-feed.pub.pem
   ```
   `APK_SIGN_KEY` — содержимое `truba-feed.pem`, `APK_SIGN_PUB` — содержимое `truba-feed.pub.pem`. Закрытый ключ в репозиторий не кладите.
3. **Actions → build → Run workflow**. После сборки включите **Settings → Pages → ветка `gh-pages`**. Эта ветка и есть фид: её не удаляют и не правят вручную.
4. Фид появится по адресу `https://lakardo.github.io/truba/<версия>/mediatek/filogic/packages.adb`.

`watch-releases` каждый день проверяет новые ImmortalWrt 25.12.x и сам собирает под них пакеты.

### 2. VPS

Нужны: Ubuntu 24.04, полноценная ВМ (KVM, VMware, Xen, Hyper-V; не контейнер), публичный IPv4 прямо на интерфейсе, SSH-ключ в `/root/.ssh/authorized_keys`.

```bash
curl -fsSLO https://raw.githubusercontent.com/LaKardo/truba/main/vps/install-vps.sh
```
```bash
sudo bash install-vps.sh install
```

Скрипт временно оставит SSH и на 22-м, и на новом порту и попросит войти по новому порту из другого окна. Без подтверждения за 120 с всё откатится. После установки:

- порт 22 и все остальные порты IP VPS уходят на Роутер, SSH самого VPS — только на новом порту;
- MTU Туннеля подобран под сеть VPS: 1380 при обычной 1500, меньше, если сеть у провайдера уже (например, 1313 при 1400);
- если модуль поддерживает AmneziaWG 3.1, Туннель сразу получает защиту заголовков (`HeaderProtectionKey`) и `DisableCookies`;
- на адресе Трубы в Туннеле (`10.77.77.1`) работает DNS-сервер для Роутера (unbound): он пересылает запросы по TLS в Cloudflare и Google, поэтому новые имена через Туннель резолвятся без лишних задержек ([ADR 0013](docs/adr/0013-tunnel-dns-server-on-vps.md)). Роутер обращается к нему сам: это первый сервер «Туннеля» по умолчанию;
- `/root/truba/router.conf` — конфиг для Роутера. Заберите его:
  ```bash
  scp -P <SSH-порт> root@<IP VPS>:/root/truba/router.conf .
  ```

Команды: `install-vps.sh install [--ssh-port N] | status | show-config | rotate-keys | random-trailers on|off | uninstall [--purge]`.

`RandomTrailers` лежит в запасе — на случай, если DPI начнёт узнавать Туннель по размерам пакетов. Он увеличивает трафик на мелких пакетах, поэтому по умолчанию выключен. Включать надо на обеих сторонах сразу:

```bash
install-vps.sh random-trailers on
```

Затем на Роутере: **Сеть → Интерфейсы → awg0 → AmneziaWG → Random Trailers → Сохранить и применить**. Выключается так же, командой `off` и снятием флага.

### 3. Роутер (ImmortalWrt 25.12, Netcraze NC-1812)

```bash
wget -O /etc/apk/keys/truba.pem https://lakardo.github.io/truba/keys/truba.pem
```
```bash
. /etc/os-release; echo "https://lakardo.github.io/truba/${VERSION}/mediatek/filogic/packages.adb" > /etc/apk/repositories.d/truba.list
```
```bash
apk update && apk add kmod-amneziawg amneziawg-tools luci-proto-amneziawg truba luci-app-truba luci-i18n-truba-ru luci-app-upnp
```

netifd узнаёт о новом протоколе `amneziawg` только при запуске, поэтому перезапустите сеть (или роутер). Без этого интерфейс Туннеля не поднимется (`proto none`, `NO_DEVICE`). Связь пропадёт секунд на 20–30:

```bash
/etc/init.d/network restart
```

Затем в LuCI:

1. **Службы → Труба → Туннель → Импорт .conf** — вставьте `router.conf` → **Сохранить и применить**.
2. **Обзор** — Туннель «работает», handshake свежий, IP Трубы виден.
3. **Маршрутизация** — Режим и Действия Категорий (Стартовые настройки уже выставлены).

При установке пакет сам создаёт зону `truba`, включает fullcone, выключает аппаратное ускорение и закрывает выход в интернет по IPv6 из `lan`. Программное ускорение он не трогает: при нём пакеты ускоренных соединений идут мимо счётчиков Трубы и мимо шейперов трафика, о чём предупреждает «Обзор». IPv6 внутри сети он тоже не трогает. При удалении пакета всё это откатывается, а Наборы правил и другие данные службы удаляются. Не выключайте IPv6 на `br-lan` (`network.lan.ipv6`): по нему mesh-узлы находят друг друга.

## Как пользоваться

| Вкладка | Что там |
|---|---|
| Обзор | Сводка: плитки «Туннель» (задержка, handshake, потери, крупные пакеты; переключатель), «Маршрутизация» (Режим, доля соединений через Туннель; переключатель), «DNS и списки» (mosdns, кэш, даты списков, следующая проверка), «Входящие» (IP Трубы, итог проверки NAT, пробросы) — каждая со ссылкой на свою вкладку; предупреждения со ссылкой туда, где их исправляют; трафик устройств по Действиям с новыми соединениями в минуту, отброшенными пакетами Блока, долей соединений через Туннель и графиком скорости за 10 минут, час или сутки. Историю скорости ведёт сам Роутер в оперативной памяти: график не рвётся, когда вкладка свёрнута или браузер закрыт, и обнуляется при перезагрузке |
| Туннель | Состояние: handshake, задержка и потери до Трубы с графиком за последние 20 проверок (10 минут при интервале 30 с), крупные пакеты (проходят ли пакеты во весь MTU), таблица Туннеля, трафик интерфейса. Импорт `.conf`, ключи и параметры маскировки AWG (в том числе AmneziaWG 3.1: защита заголовков, DisableCookies, RandomTrailers), контроль Туннеля и Аварийная блокировка |
| Маршрутизация | Режим, зоны, сколько подсетей и IP сейчас в наборах по Действиям, Политики устройств по MAC («Всё в туннель», «Всё напрямую», «По правилам») с именем и IP устройства, таблица всех Категорий с Действиями для каждого Режима и фильтром по Действию |
| DNS и списки | Состояние DNS: mosdns, попадания в кэш, заполнение кэша. DNS: серверы для «Туннель» и «Напрямую», кэш (в том числе ленивый), перехват DNS, срок IP из DNS в наборах. Наборы правил: версии, последняя и следующая проверка, «Обновить сейчас» и откат (применяется в фоне), расписание, источники |
| Входящие | Проверка NAT: итог последней проверки (сама запускается после подъёма Туннеля) и кнопка; UPnP/NAT-PMP на Туннеле и его действующие пробросы, пробросы портов из зоны `truba` |
| Диагностика | «Проверить домен/IP» — какая Категория и какое Действие сработают и почему; «Проверка Туннеля» — ping Трубы пакетами трёх размеров до полного MTU; журнал Трубы и mosdns с фильтром (Труба, mosdns, предупреждения и ошибки) |

Любое изменение применяется кнопкой **«Сохранить и применить»**: служба `truba` сама включает или снимает правила nftables, маршруты, mosdns, перенаправление dnsmasq, cron и контроль Туннеля.

Если применить не удалось, служба не останавливается и DNS сети не пропадает: действуют прежние правила, а после перезагрузки — последняя удачная копия, сохранённая на флеше ([ADR 0006](docs/adr/0006-failed-apply-keeps-last-good-rules.md)). Ошибку и то, что действует вместо неё, показывает «Обзор». Неверное значение в настройках (например, MAC или адрес DNS-сервера с опечаткой) пропускается, вместо него берётся значение по умолчанию, и «Обзор» об этом предупреждает. Скачанный Набор правил, который не разбирается, текущий не заменяет.

Из командной строки (`truba` без аргументов — список команд):

```bash
truba status
```
```bash
truba check gosuslugi.ru
```
```bash
logread -e truba
```

## Обновление

**Пакеты Роутера** обновляйте вместе — интерфейс и служба одной версии:

```bash
apk update && apk upgrade truba luci-app-truba luci-i18n-truba-ru
```

**Труба.** Скачайте свежий `install-vps.sh` и запустите `install` ещё раз: ключи и порты сохранятся, а очередь, заголовки ядра, MTU и DNS-сервер для Роутера приведутся к текущим. Если на вкладке **DNS и списки** среди серверов «Туннеля» нет `udp://10.77.77.1`, поставьте его первым. Строка `MTU Туннеля` в выводе `install-vps.sh status` показывает действующее значение. Если оно поменялось, поставьте его и на Роутере: **Службы → Труба → Туннель → MTU → Сохранить и применить** (или импортируйте `router.conf` заново). Повторный `install` параметры AWG не меняет. Чтобы перейти на новую версию протокола (например, AmneziaWG 3.1), выполните `rotate-keys` и импортируйте `router.conf` в Роутер заново.

**ImmortalWrt.** Обновляйте Роутер только после того, как в фиде появился каталог новой версии (`watch-releases` собирает его автоматически). После sysupgrade настройки и ключ фида сохраняются, а `/etc/truba/reinstall.sh` из `rc.local` сам ставит пакеты заново. Если модуля ядра под новую версию ещё нет, Туннель не поднимется: скрипт пишет в журнал, как доставить модуль, когда сборка появится.

## Проверки

Все проверки идут в Docker, независимые части — параллельно:

```bash
bash tests/run.sh
```

Что проверяет каждая часть и как запускать их по отдельности — в [tests/README.md](tests/README.md). На pull request CI гоняет те же части. Приёмочные тесты на живой сети (Full cone по RFC 5780, входящие, утечки) — в [docs/roadmap.md](docs/roadmap.md#приёмочные-тесты).
