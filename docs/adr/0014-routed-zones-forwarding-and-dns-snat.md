# Зоны Маршрутизации: перенаправление в `truba` ведёт Труба, DNS из чужих подсетей — с подменой источника

- Статус: принято, 2026-10-11

## Контекст

На вкладке «Маршрутизация» выбираются зоны межсетевого экрана (`truba.main.zone`), устройства которых маршрутизирует Труба: их интерфейсы попадают в набор `lan_if`. По умолчанию это `lan`. Если выбрать ещё одну зону — например, зону mesh-VPN, чтобы её узлы выходили в интернет через Роутер по Категориям, — ломались две вещи.

- **Нет перенаправления в `truba`.** Установка заводила только `lan → truba` (`firewall.lan_truba`). Трафик устройств другой зоны, которому Труба выбрала «Туннель», уходил в `awg0`, и fw4 отбрасывал его: перенаправления из этой зоны в зону `truba` нет. Чинилось только вручную, на другой странице LuCI.
- **DNS узлов из чужих подсетей.** Перехват DNS (`dns_hijack`) отправляет порт 53 со всех интерфейсов `lan_if` в dnsmasq Роутера. dnsmasq по умолчанию запущен с `--local-service` (`localservice 1`) и молча не отвечает адресам вне подсетей своих интерфейсов. У интерфейса mesh-VPN адрес обычно `/32`: его подсеть — сам адрес, и все узлы сети для dnsmasq чужие. Перехват оставлял их без DNS. Исключить такие интерфейсы из перехвата мало: в ImmortalWrt dnsmasq по умолчанию сам перенаправляет к себе UDP 53 со всех интерфейсов (`dns_redirect 1`, приоритет −95), и запросы всё равно попадают к нему.

## Рассмотренные варианты

Перенаправления:

- **Только предупреждение** на «Обзоре», что у выбранной зоны нет перенаправления в `truba`. Выбор зоны уже говорит, что её трафик должен идти через Туннель; второй шаг на другой странице — та же ошибка, только с подсказкой. Отклонено.
- **Пропускать такой трафик своей цепочкой forward.** accept в одной базовой цепочке не отменяет drop в цепочке fw4 на том же хуке. Невозможно.

DNS:

- **Только предупреждение.** DNS зоны не работает, пока владелец не перенастроит dnsmasq. Отклонено.
- **Не перехватывать DNS с таких интерфейсов.** Не помогает при `dns_redirect 1` (по умолчанию в ImmortalWrt), а без него Категории доменов на узлы сети не действуют. Отклонено.
- **Выключить `localservice`** (с бэкапом, как `noresolv`). dnsmasq стал бы отвечать любому адресу, которому межсетевой экран открывает вход: при открытом входе из `wan` — открытый резолвер. Отклонено.
- **Список интерфейсов dnsmasq** (`interface`). При явном списке `--local-service` не действует, но dnsmasq перестаёт слушать DNS и раздавать DHCP на интерфейсах вне списка — решать это за владельца нельзя. Отклонено.

## Решение

- **Перенаправления следуют за зонами.** При каждом применении, и при выключенной Маршрутизации тоже, у каждой выбранной зоны, которая есть в межсетевом экране, должно быть перенаправление в `truba`. Если никакого нет, Труба заводит своё — секцию `<зона>_truba` (`lan_truba` — то же имя, что прежде заводила установка). Свои секции зон, которые больше не выбраны или удалены, убираются. Перенаправления, которые владелец завёл сам (под любым другим именем), засчитываются и не трогаются. Межсетевой экран перезагружается, только если что-то изменилось. Остановка службы перенаправления не снимает; удаление пакета убирает все перенаправления в `truba` вместе с зоной.
- **DNS из чужих подсетей — от имени Роутера.** Набор `local4` — подсети всех IPv4-адресов Роутера, то есть то, что dnsmasq считает локальным. Цепочка `dns_snat` (nat input, `srcnat`) подменяет источник DNS с интерфейсов `lan_if` и адресов вне `local4` на адрес Роутера, к которому пришёл запрос (`snat ip to ip daddr`). После перехвата это адрес интерфейса, и dnsmasq отвечает «себе»; ответ ядро возвращает устройству по conntrack. Устройства из подсетей Роутера dnsmasq видит под их адресами. Набор обновляется вместе с `bypass4` при смене адресов интерфейсов; новая подсеть, пока её нет в наборе, получает лишнюю подмену — это безвредно, dnsmasq ей и так ответил бы.

## Последствия

- Выбрать зону на вкладке «Маршрутизация» достаточно: её устройства идут через Туннель по Категориям, их DNS перехватывается и получает ответ — в том числе у узлов mesh-VPN за интерфейсом с адресом `/32` и у устройств за другим маршрутизатором в домашней сети.
- Труба меняет конфигурацию межсетевого экрана не только при установке, но и при каждом применении. Если в редакторе зоны LuCI снять у выбранной зоны перенаправление в `truba`, следующее применение вернёт его: чтобы зона шла мимо Туннеля, её убирают из «Маршрутизация → Зоны». Отключённое (`enabled 0`) перенаправление владельца засчитывается — своё Труба тогда не заводит.
- В журнале dnsmasq запросы узлов из чужих подсетей видны от адреса Роутера.
- Если у dnsmasq задан список интерфейсов (`interface`) и интерфейса выбранной зоны в нём нет, dnsmasq на нём не слушает, и перехват DNS этой зоны не работает. Подмена источника тут не помогает.
- В тестах mesh-VPN проверяется и как зона Маршрутизации: без перенаправления fw4 отбрасывает трафик узла в Туннель, с ним — пропускает; dnsmasq не отвечает узлу, пока зона не выбрана, и отвечает после.

## Пересмотреть, если

- dnsmasq начнёт решать, кому отвечать, не по подсетям интерфейсов — подмена может стать лишней или недостаточной;
- понадобится выбранная зона без перенаправления в `truba` — тогда перенаправления должны стать настройкой.
