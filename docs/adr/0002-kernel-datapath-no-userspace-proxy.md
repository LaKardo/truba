# Трафик Туннеля идёт через ядро, а не через программный прокси

- Статус: принято

## Контекст

Привычный для `.dat`-файлов путь — Xray, sing-box или mihomo в режиме TPROXY или TUN. Тогда соединения в Туннель открывает сам прокси, и ни FullCone NAT ImmortalWrt, ни проброс портов к устройствам домашней сети на этот трафик не действуют (ADR 0001).

## Решение

Трафик Туннеля идёт через ядро: метки пакетов (fwmark), отдельная таблица маршрутизации `77` и наборы адресов nftables. Наборы правил только сортируют трафик: geoip превращается в наборы подсетей, а для geosite DNS-резолвер кладёт IP ответов в наборы nftables (ADR 0003).

## Последствия

- Правила по доменам работают только для устройств, которые резолвят имена через Роутер. Шифрованный DNS в браузере (DoH) их обходит. В Режиме «Всё в туннель» это безопасно: такой трафик просто уходит в Туннель.
- Если один IP обслуживает домены с разными Действиями (общий CDN), разделить их нельзя: решает фиксированный порядок проверки наборов, а не домен. Между Категориями Туннель побеждает Напрямую. Домены «По режиму» в наборы не попадают, а IP из DNS действуют ограниченный срок (ADR 0007).
- На Роутере нет процесса, через который идёт трафик: нечему падать под нагрузкой, и скорость ограничена только ядром и AmneziaWG.

## Пересмотреть, если

- понадобится маскировка, которой нет у AmneziaWG в ядре (например, туннель поверх TLS). Тогда прокси — только для исходящего трафика Действия «Туннель», без входящих и без Full cone.
