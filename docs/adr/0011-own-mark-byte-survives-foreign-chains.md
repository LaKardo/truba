# Метки Трубы переживают чужие цепочки nftables

- Статус: принято

## Контекст

Решение о пути соединения Труба держит в метках (ADR 0002): meta mark пакета ведёт в таблицу 77, ct mark хранит решение для всех пакетов соединения. На Роутере могут работать и другие службы, которые пишут в те же метки:

- шейпер трафика в postrouting перезаписывает ct mark целиком (например, `ct mark set ip dscp | 0x80`);
- прозрачный прокси для трафика самого Роутера в цепочке output ставит свою meta mark почти всему исходящему и уводит его своим `ip rule` с точной меткой в свою таблицу;
- балансировщик каналов пользуется битами meta mark.

Если решение Трубы перезаписано, ответы на входящие через Туннель уходят в `wan` и соединение разваливается; свои сокеты Роутера с меткой «Туннель» (mosdns к DNS-серверам «Туннеля», «Проверить NAT») идут мимо Туннеля; внешние пакеты самого Туннеля уходят в чужую таблицу или заворачиваются в `awg0` — петля.

## Решение

- **Свой байт.** Метки Трубы — только байт `0x00ff0000`: TUNNEL `0x00010000`, DIRECT `0x00020000`, INBOUND `0x00040000`. Любая запись — `mark & 0xff00ffff | X`: остальные биты meta mark и ct mark не трогаются. `ip rule` 1000 сравнивает метку по маске `0x00ff0000`.
- **Решение — последним.** Решение держится в meta mark каждого пакета и записывается в ct mark в цепочке `persist` (postrouting, priority 300) — после всех, кто пишет ct mark раньше. Входящие через Туннель метятся INBOUND на каждом пакете, а не только на первом.
- **Свои сокеты.** Цепочка `output` (route hook, priority `mangle + 10`) возвращает байт Трубы из метки сокета (`socket mark`, модуль `kmod-nft-socket`): после чужих цепочек output решение берётся у сокета, а не у пакета. Route-хук при смене метки маршрутизирует пакет заново: правило 1000 с маской срабатывает, а чужое правило с точной меткой — уже нет.
- **Сам Туннель — только напрямую.** Первое правило `output`: пакеты к IP Трубы получают DIRECT. Это внешние зашифрованные пакеты AmneziaWG: они проходят output ещё раз и несут сокет исходного пакета с его меткой «Туннель», и без этого правила `socket mark` заворачивал бы Туннель в себя. Метка DIRECT в байте Трубы заодно ломает чужие правила с точной меткой.

## Последствия

- Труба работает рядом с такими службами без исключений в их настройках и без порядка запуска.
- `kmod-nft-socket` — зависимость пакета. Без модуля правила `socket mark` нет (в журнал пишется предупреждение), остальное работает.
- Не защищает от чужих правил, чья маска включает байт `0x00ff0000`, и от перенаправления DNAT в nat output (прокси в режиме redirect): метками это не лечится.
- В тестах чужая цепочка, перезаписывающая ct mark и meta mark, проверяется на настоящем WireGuard: на veth петля Туннеля не воспроизводится.

## Пересмотреть, если

- другая служба займёт байт `0x00ff0000` — тогда байт Трубы должен стать настройкой;
- понадобится маршрутизация по меткам для IPv6 (ADR 0005).
