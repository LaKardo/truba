# IP из DNS действуют в наборах ограниченный срок

- Статус: принято

## Контекст

mosdns кладёт IP ответов для Категорий geosite с явным Действием в наборы `gs_tunnel4` и `gs_direct4`. Без срока такие наборы сбрасываются только при смене Режима и Действий или при обновлении geosite, то есть могут жить неделями.

Домены «По режиму» в наборы не попадают. Поэтому в Режиме «Всё в туннель» адрес CDN, общий у домена Категории «Напрямую» (например, `category-ru` на Cloudflare) и у зарубежного сайта без Категории, оказывается в `gs_direct4`, и новые соединения этого сайта идут через провайдера. Правило «Туннель побеждает Напрямую» на них не действует: оно разрешает конфликт только между Категориями с явным Действием. Без срока такой адрес уводит трафик и после того, как домен Категории сменил адрес.

## Рассмотренные варианты

- **Отдельный набор IP доменов «По режиму»** и правило «IP в `gs_direct4` и в этом наборе → Туннель». Обещание «Туннель побеждает Напрямую» выполнялось бы и для них, но это второй большой набор (почти все зарубежные адреса), ограничение TTL ещё и для ответов «По режиму» и усложнение Приоритета.
- **Срок у наборов и честная формулировка в документах** — выбрано.
- **Наборы без срока** — устаревшие адреса держатся до следующего сброса.

## Решение

- Наборы `gs_*` создаются с `flags timeout`. Срок по умолчанию — сутки: `truba.dns.set_timeout`, 600…604800 с, 0 — без срока. На вкладке «DNS и списки» это «Дополнительно → Срок адресов из DNS в наборах».
- mosdns добавляет элементы без своего срока, и они получают срок набора.
- При переносе в новую таблицу (применение настроек) элемент сохраняет оставшийся срок. Перенос его не продлевает: иначе частые применения держали бы устаревшие адреса вечно. Если новый срок набора короче, элемент укорачивается до него.

## Последствия

- Устаревшая связь «адрес CDN — домен Категории» действует не дольше срока. Активный конфликт, когда оба домена отвечают этим адресом прямо сейчас, срок не решает: адрес снова попадает в `gs_direct4` с каждым ответом. Это ограничение маршрутизации по IP (ADR 0002). «Проверить домен/IP» показывает такой адрес с причиной «IP из DNS».
- Повторный ответ DNS срок элемента не продлевает: mosdns 5.3.3 добавляет элемент без срока, а ядро не обновляет срок существующего элемента. Когда срок истёк, адрес возвращается со следующим ответом. До этого новые соединения устройства, которое ещё пользуется прежним ответом, идут по geoip или Режиму — не дольше `ttl_max` (300 с), раз в срок на адрес. Это то же окно, что и после сброса наборов при обновлении geosite: ради него TTL классифицированных ответов и ограничен. Открытые соединения путь не меняют — решение уже в ct mark.
- Продлевать срок по трафику (`update` из правил nftables) не стали: занятый адрес CDN тогда не истекал бы никогда, а это именно тот случай, ради которого срок введён.

## Пересмотреть, если

- конфликт общих CDN-адресов станет заметным на практике — тогда вариант с набором IP доменов «По режиму»;
- mosdns научится продлевать срок существующего элемента.
