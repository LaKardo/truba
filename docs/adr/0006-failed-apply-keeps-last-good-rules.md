# Если применить настройки не удалось, действуют последние удачные правила

- Статус: принято

## Контекст

dnsmasq пересылает все запросы в mosdns (`noresolv`, `server=127.0.0.1#5335`). `truba apply` может упасть посреди перезагрузки службы: nft не принял таблицу из-за опечатки в UCI, распаковщик не разобрал выпуск `.dat`. Если в этот момент procd снимет mosdns, а dnsmasq продолжит слать запросы в закрытый порт, DNS всей домашней сети пропадёт и сам не вернётся.

## Рассмотренные варианты

- **Оставить сеть без DNS** до исправления.
- **Вернуть dnsmasq к DNS провайдера** — запросы Категорий «Туннель» утекают мимо Туннеля.
- **Держать последние удачные правила** — выбрано.

## Решение

- `nft -f` атомарен: если новая таблица не загрузилась, действует прежняя. Конфиг mosdns пишется только после загрузки таблицы, поэтому действующий конфиг всегда ей соответствует, и mosdns не перезапускается.
- После каждого удачного применения на флеш сохраняется копия (`/etc/truba/good`): правила nftables без счётчиков и без IP из DNS (их снова наберёт mosdns), конфиг mosdns без API и списки доменов, на которые он ссылается. Пишется только то, что изменилось.
- После перезагрузки прежней таблицы в ядре нет, и при ошибке загружается эта копия.
- Нет и копии (не было ни одного удачного применения) — правил Трубы нет, трафик и так идёт напрямую, и dnsmasq возвращается к обычному DNS.
- Нужен ли mosdns, решает apply и пишет это в `applied.json`. init-скрипт открывает инстансы procd по нему, а не по UCI, — и при ошибке тоже.

## Последствия

- Ошибка применения не останавливает ни mosdns, ни контроль Туннеля. «Обзор» показывает ошибку и что действует вместо неприменённого.
- Неверное значение в UCI (MAC, адрес DNS-сервера, порт, адрес для ping) до nft и mosdns не доходит: оно пропускается, вместо него берётся значение по умолчанию, и «Обзор» перечисляет пропущенное.
- `update-lists` разбирает скачанный файл до замены текущего. Если текущие списки всё же не распаковываются, apply возвращает предыдущие и предупреждает об этом.
- Копия на флеше переживает sysupgrade (`/etc/truba/` в keep.d) и удаляется вместе с пакетом.

## Пересмотреть, если

- появится сценарий, где DNS провайдера при ошибке допустим (например, Роутер без Действия «Туннель»), — тогда это отдельный переключатель, а не поведение по умолчанию.
