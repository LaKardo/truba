# Если применить настройки не удалось, действуют последние удачные правила

- Статус: принято
- Дата: 2026-10-09

dnsmasq пересылает все запросы в mosdns (`noresolv`, `server=127.0.0.1#5335`). Раньше любая ошибка `truba apply` при reload (nft не принял таблицу из-за опечатки в UCI, распаковщик не разобрал новый выпуск `.dat`) обрывала `start_service` до открытия инстансов. rc.common всё равно передавал procd пустой список, procd останавливал mosdns и watchdog, а dnsmasq продолжал слать запросы в закрытый порт: DNS всей домашней сети пропадал и сам не возвращался. Рассматривались три поведения: оставить сеть без DNS, вернуть dnsmasq к DNS провайдера (запросы Категорий «Туннель» утекают мимо Туннеля) или держать последние удачные правила. Выбрано третье.

- `nft -f` атомарен: если новая таблица не загрузилась, действует прежняя. Конфиг mosdns пишется только после загрузки таблицы, поэтому действующий конфиг всегда ей соответствует, и mosdns не перезапускается.
- После каждого удачного применения на флеш сохраняется копия (`/etc/truba/good`): правила nftables без счётчиков и без IP из DNS (их снова наберёт mosdns), конфиг mosdns без API и списки доменов, на которые он ссылается. Пишется только то, что изменилось.
- После перезагрузки прежней таблицы в ядре нет, и при ошибке загружается эта копия.
- Нет и копии (не было ни одного удачного применения) — правил Трубы нет, трафик и так идёт напрямую, и dnsmasq возвращается к обычному DNS.
- Нужен ли mosdns, решает apply и пишет это в `applied.json`; init-скрипт открывает инстансы по нему, а не по UCI.

## Последствия

- Ошибка применения не останавливает ни mosdns, ни watchdog. «Обзор» показывает ошибку и что действует вместо неприменённого.
- Неверное значение в UCI (MAC, адрес DNS-сервера, порт, адрес для ping) до nft и mosdns не доходит: оно пропускается, вместо него — значение по умолчанию, «Обзор» перечисляет пропущенное.
- `update-lists` разбирает скачанный файл до замены текущего. Если текущие списки всё же не распаковываются, apply возвращает предыдущие.
- Копия на флеше переживает sysupgrade (`/etc/truba/` в keep.d) и удаляется вместе с пакетом.
