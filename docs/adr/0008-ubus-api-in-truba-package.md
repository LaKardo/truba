# ubus-API Трубы — в пакете `truba`, объект регистрирует один плагин

- Статус: принято

## Контекст

ubus-объект `truba` (rpcd-плагин: `status`, `rates`, `check`, проверки в фоне…) — тонкая обёртка над командной строкой `truba`. Если API лежит в `luci-app-truba`, а CLI — в `truba`, они меняются вместе, а версии пакетов — порознь: новый интерфейс может встать на старую службу, у которой ещё нет нужной команды. Без LuCI объекта не было бы вовсе, и скрипты или уведомления не могли бы спросить состояние через ubus.

У rpcd (2026.07.19, `ucode.c`) есть ошибка: если два плагина регистрируют один объект, неудавшуюся регистрацию он освобождает, но оставляет в своём списке, и следующий плагин пишет в освобождённую память. Порядок загрузки плагинов — как отдаёт `readdir`, а не по имени. На NC-1812 rpcd от этого падал на HUP (код 139), procd переставал его поднимать, и LuCI не пускал: вход отвечал RPCError и «неверный пароль». В Docker на x86 и в эмуляции aarch64 падение не воспроизводится.

`luci-app-truba` до 1.0.0-r14 содержал свой плагин этого объекта — `/usr/share/rpcd/ucode/truba.uc`, а его зависимость была `truba (>=0)`, так что службу можно обновить без интерфейса.

## Решение

- Плагин лежит в пакете `truba`: `/usr/share/rpcd/ucode/truba-api.uc`, зависимость — `rpcd-mod-ucode`. Имя файла — не `truba.uc`, чтобы apk не делил один путь между двумя пакетами.
- `luci-app-truba` — только интерфейс: представления, меню, ACL, перевод. Он зависит от `truba` той же версии.
- Объект `truba` регистрирует ровно один плагин. Пока на Роутере есть старый `truba.uc`, `truba-api.uc` возвращает пустой набор объектов: объект остаётся за старым плагином, и старый интерфейс работает с ним, как раньше (CLI совместим). Обновление интерфейса удаляет `truba.uc`, и после HUP объект переходит к `truba-api.uc`.
- postinst `truba` шлёт rpcd HUP (rpcd перезапускается сам и сохраняет сессии LuCI), а если rpcd не запущен — запускает его. postrm тоже шлёт HUP.

## Последствия

- API и CLI — в одном пакете и одной версии. Проверка `luci` сверяет вызовы интерфейса с методами плагина и с ACL.
- `ubus call truba status` работает и без LuCI. Права на методы задаёт ACL интерфейса; без `luci-app-truba` объект доступен только root.
- Тест проверяет, что при старом плагине `truba-api.uc` не регистрирует ничего и rpcd переживает HUP. Само падение на x86 не воспроизводится, поэтому проверяется отсутствие второй регистрации.
- Новые плагины Трубы не должны повторять имя объекта, даже временно.

## Пересмотреть, если

- обновление с `luci-app-truba` до 1.0.0-r14 станет неактуальным — проверку старого плагина можно убрать вместе с её тестом;
- в rpcd исправят повторную регистрацию объекта.
