# Собственный apk-фид поверх стоковой ImmortalWrt

- Статус: принято

## Контекст

В фидах ImmortalWrt 25.12 нет AmneziaWG. Модули ядра из сторонних фидов собраны под ядро обычной OpenWrt и не совпадают с ImmortalWrt по vermagic.

## Рассмотренные варианты

- **Собственный образ через ImageBuilder** — Роутер теряет стоковую прошивку и её обновления, каждую версию ImmortalWrt нужно пересобирать целиком.
- **Пакеты поверх стоковой прошивки из своего фида** — выбрано.

## Решение

- `kmod-amneziawg`, `amneziawg-tools`, `luci-proto-amneziawg`, `truba` и `luci-app-truba` собирает CI репозитория (GitHub Actions + ImmortalWrt SDK для `mediatek/filogic`) и публикует подписанным apk-фидом в GitHub Pages (ветка `gh-pages`) с каталогом под каждую версию ImmortalWrt.
- CI каждый день проверяет выход новых версий ImmortalWrt 25.12.x и собирает под них модуль ядра заранее, до того как Роутер обновится.
- После sysupgrade пакеты ставит заново `/etc/truba/reinstall.sh` из `/etc/rc.local`. Настройки, ключ фида и сам скрипт сохраняются через `/lib/upgrade/keep.d`.

## Последствия

- sysupgrade сохраняет `/etc/config/dhcp`, где dnsmasq направлен в mosdns, а mosdns после прошивки ещё нет. Поэтому `reinstall.sh` первым делом возвращает dnsmasq к значениям из бэкапа Трубы (`/etc/truba/state/dnsmasq.json`), а после установки перезапускает сеть: обработчик протокола `amneziawg` netifd находит только при запуске.
- Пока под новую версию ImmortalWrt нет сборки, обновлять Роутер нельзя. Скрипт переустановки пишет об этом в журнал и не ставит чужой модуль.
- Ветка `gh-pages` — это и есть фид: её нельзя удалять или переписывать вручную. Сборка берёт оттуда уже собранный AmneziaWG, если его источники не менялись.

## Пересмотреть, если

- AmneziaWG появится в фидах ImmortalWrt с модулем под её ядро — тогда своему фиду остаются только `truba` и `luci-app-truba`;
- понадобится другой Роутер (другая платформа) — это новый `target/subtarget` в матрице сборки.
