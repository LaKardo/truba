# Проверки

Всё идёт в Docker на настоящей ImmortalWrt (rootfs 25.12): Linux, CI или Windows из Git Bash с Docker Desktop. Нужен `docker` с правом `--privileged`. Почему так — [ADR 0012](../docs/adr/0012-tests-on-real-immortalwrt-in-docker.md).

```bash
bash tests/run.sh
```

Без аргументов — все части разом: каждая в своём контейнере, вывод — в журнал части, в конце таблица со временем и провалы. Одна часть — вывод сразу в консоль:

```bash
bash tests/run.sh router-dns
```

`router` — все части Роутера; можно перечислить несколько частей через пробел.

## Части

| Часть | Где | Что проверяет | Время |
|---|---|---|---|
| `units` | `unit/units.uc` | Модули без procd и сети: план и порядок Категорий, Приоритет, правила nftables и конфиг mosdns против эталонов `golden/` (и `nft -c`), чтение настроек и пропуск неверных значений, «Проверить домен/IP» на синтетических Наборах правил (`domain:`, `full:`, `regexp:`, `keyword:`, Блок, узкие раньше широких), история скорости (точки, минуты, сроки, разрывы), методы ubus-API, которые читают файлы | секунды |
| `dat` | `unit/dat.uc` | Распаковщик на настоящих выпусках из `dat.pin`: записи один в один, вложенность Категорий, точные числа снимка | секунды |
| `luci` | `luci/static.mjs` | Синтаксис интерфейса, полнота русского перевода, схемы адресов DNS как у службы, каждый вызов `truba.*` есть в ubus-API и в ACL | секунды |
| `vps` | `vps/test.sh` | `install-vps.sh`: shellcheck, параметры AWG 1.x/2.x/3.1, конфиги обеих сторон, правила nft в ядре, sysctl, заголовки ядра, MTU по сети VPS, DNS для Роутера (unbound: конфиг с файлами пакета, старт до Туннеля, слушает и отвечает только Роутеру), смена порта SSH | ~35 с |
| `router-net` | `router/net.sh` | Что ставит установка; правила, маршруты и dnsmasq после применения; входящие через Туннель; свои сокеты Роутера; чужие цепочки nftables (ADR 0011); учёт трафика; Политика устройства; Аварийная блокировка; Маршрутизация выкл; «Выборочный»; teardown и uninstall | ~40 с |

| `router-lists` | `router/lists.sh` | Обновление и откат Наборов правил (в том числе через rpcd в фоне), обновление без изменений, файл, который не разбирается, нечитаемые текущие списки, свежая установка без списков | ~30 с |

| `router-stats` | `router/stats.sh` | История скорости под procd без браузера, rpcd `rates`, перезапуск процесса, разрыв при новом отсчёте | ~55 с |

Время — локально, с подготовкой стенда; все части разом — столько, сколько самая долгая.

## Стенд Роутера

Каждая часть `router-*` начинается с `router/stand.sh`: контейнер ImmortalWrt под настоящим procd/netifd/fw4, пакет `truba` из `router/truba/files`, домашняя сеть в netns `lanhost` и Туннель — настоящий WireGuard до netns `vps` (ядро шифрует пакеты и шлёт внешние своим UDP-сокетом, как AmneziaWG; на veth петли Туннеля не видны). Модуля amneziawg в ядре контейнера нет, поэтому `awg` — обёртка над `wg`.

Особенности стенда, о которые легко споткнуться:

- часовой пояс образа — +0800: время cron Трубы на стенде — местное, 12:00 UTC = 20:00;
- dnsmasq OpenWrt сам отвечает на `*.test`, а `.example` и прочие зарезервированные имена входят в geosite `private` — синтетические домены живут в зоне `trubatest`;
- ответы из частных и test-net диапазонов dnsmasq отбрасывает (stop-dns-rebind) — подставные DNS-серверы отвечают адресами `44.0.0.x`;
- под procd у контейнера нет интернета: зависимости ставятся в образ `truba-test:<хеш>` заранее (имя — по базовому образу и списку пакетов `TEST_PKGS`, поэтому другой список даёт новый образ);
- `/proc/kmsg` хоста подменён на `/dev/null`: иначе logd может повиснуть, а с ним `logread`, rpcd и LuCI;
- в ядре WSL2 нет `nft_socket`: проверка метки своих сокетов при чужой цепочке там пропускается (`skip`).

## Переменные

| Переменная | Что делает |
|---|---|
| `JOBS=N` | Не больше N частей одновременно (по умолчанию — все сразу) |
| `DAT_FRESH=1` | Свежие Наборы правил из release-веток вместо закреплённых (так каждый день работает `upstream-lists.yml`) |
| `DAT_DIR=…` | Свой каталог с `geoip.dat` и `geosite.dat` |
| `DAT_CACHE=…` | Где хранить скачанные закреплённые выпуски (по умолчанию `~/.cache/truba-tests`) |
| `UPDATE_GOLDEN=1` | Записать эталоны `golden/` заново (часть `units`); разница видна в диффе |
| `UI_OUT=…` | Куда сложить снимки вкладок (часть `ui`; в CI — артефакт PR) |
| `LOG_DIR=…` | Куда писать журналы частей |
| `IMAGE_CACHE=…` | Каталог архивов образов Docker: образ берётся оттуда, а не из Docker Hub. В CI он хранится в `actions/cache` и обновляется раз в неделю |

## Как добавить проверку

- **Логика без ядра и служб** (разбор, расчёт, генерация) — в `unit/units.uc`. Это секунды, и здесь же — эталоны.
- **Правила, маршруты, службы** — в ту часть `router/*.sh`, к которой она относится. Сценарий начинается с `. /repo/tests/router/stand.sh`; функции — в `lib/check.sh` (`check`, `wait_for`, `reload`, `in_set`, `probe`…). Составное условие с этими функциями — через `check ИМЯ eval '…'`: в `sh -c` их нет.
- **Не ждать по таймеру.** После `reload` правила уже в ядре; то, что procd перезапускает сам (mosdns, watchdog), ждите по условию через `wait_for`.
- **Новая часть** — файл `router/<имя>.sh`, имя `router-<имя>` в `ROUTER_PARTS` в `run.sh` и в матрицах `tests.yml` и `upstream-lists.yml`. Части независимы: у каждой свой стенд.
- **Наборы правил** закреплены в `dat.pin`. Пропал выпуск у источника — поднимите теги, SHA-256 и числа снимка в `unit/dat.uc`.
